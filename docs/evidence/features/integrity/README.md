# Transaction integrity infrastructure (issue #3)

## Integration contract

This is shared backend infrastructure, not delivery of the domain endpoints or review screens. It uses the foundation's existing migrations; no schema or API routes are added.

- Construct `transactions.Manager{DB: writerDB}` with `database.Open`, whose driver uses serialized `BEGIN IMMEDIATE`. Repositories receive only statement methods, not commit/rollback. Errors, cancellation and panics roll back. SQLite busy/locked errors map to a safe 503; `transactions.WriteError` maps known conflicts to 409 and hides other internal errors.
- Compose `transactions.Service` with that manager, `transactions.Store` and a `contracts.AuditWriter`. Call `Mutate` with a mandatory current-authorization callback and a work callback. Authorization runs before replay lookup **inside** the transaction. The callback must check current session/access revision and record visibility, including related records, using its owning policy service. The work callback checks versions and domain prerequisites and returns result plus audit event. Business, audit and duplicate outcome commit together. Return HTTP success only after `Mutate` succeeds.
- Use `Digest` on an already strictly decoded, validated typed request. It retains exact integer strings, sorts object keys and ignores formatting. It is not a raw JSON request validator. Keys are UUIDs, namespaced by principal and operation. A changed digest conflicts, and a replay never repeats business work. Never prune retained source keys. The baseline schema has no result version column: `idempotency_records.result_id` is an internal JSON `{id,version}` reference envelope. Consume it via `Store.Lookup`, not direct scalar-ID joins. It stores no response bodies or secrets. Replays return the original status/reference/version; domain handlers resolve only currently authorized representations.
- `NewMetadata` and `Advance` preserve creator, ID, creation time and project, using fixed-millisecond UTC timestamps. An update statement must also predicate its expected version and check affected rows. `CheckTransition` accepts only workflow-owned edges. `CheckRetirement` permits reasoned archive/cancel/reversal, never deletion. Existing foreign keys and immutable-history triggers retain references.
- `ReviewPredicate` supplies SQL and bound parameters for alias `r`; apply it **before pagination**. It reads current active/setup-complete user and project assignments, excludes creators even for Administrators, and routes purchase orders using the persisted submitter-role snapshot. Supported queues: site logs, purchase orders, work orders, expenses, reservations and booking cancellation records. With no eligible reviewer nothing is auto-approved.
- `Decide` uses the same predicate and authoritative creator/state/version. The domain callback validates evidence and applies all domain effects, updating the status and version exactly once. The helper verifies that outcome, appends a typed review decision (or cancellation's own decision fields), and returns the audit event to `Service.Mutate`. Do not call it as a standalone committed operation without the service's audit boundary. Domain cancellation code still owns claim release, terms and refund rules. Submission code owns draft-to-submitted validation and audit; queues derive pending membership from persisted status, not a second mutable queue.
- `contracts.PostingConfiguration` declares readiness and currency locking for use in the posting transaction. Exact amounts/cost-source contracts stay independent of concrete domain packages; workflow owners still decide evidence, recognition, allocation and reversal eligibility.

Concrete posting integration uses `posting.Configuration{}`. `RequireReady` checks explicitly chosen currency/precision, confirmed IANA timezone, recorded policy/retention metadata and operating countries; `LockCurrency` rechecks readiness and makes the first lock transactional. Use `money.ParseQuantity`, `ParsePrice` and `ParseMinor` for exact inputs, then `LineMinor` or `TotalMinor` for per-line half-up rounding and bounded totals. `MatchCostSource` rejects mismatched shared source identity, project, category, commitment or amount; it does not create recognition entries or decide approval eligibility.

Authentication services can use the audit writer within `Manager.WithinWrite` for unknown-user events without creating a fictitious staff account. They must not persist raw login/reset requests or session/token material as idempotency outcomes.

Use `writer.New()` for the concrete safe writer. Structured changes are closed field/value allowlists (enums, exact integers, dates and booleans), not arbitrary serialized business objects. Extend those reviewed allowlists when adding a new safe field rather than writing raw request bodies. Review reasons retain bounded human prose, with credential-assignment/token/diagnostic/path/control-character rejection. This is defense in depth, not proof that arbitrary prose cannot contain a secret; callers must never feed credentials, request dumps or internal errors to the writer. Unknown action/resource/field combinations fail closed and roll back the mutation.

## Evidence

Required checks are run from the repository root; each uses disposable real SQLite and migrations, not an operator database. The transaction suite exercises after-audit fault rollback, atomic review history, stale versions, changed-payload conflicts, replay authorization, two separate competing writer pools, durable result lookup, retained project references, independent Administrator review, assignment/deactivation filtering, panic/cancellation rollback and safe HTTP errors.

Validation results are recorded in `validation.md`. Domain/browser acceptance, later generated property campaigns, and full release acceptance are not claimed by these infrastructure tests.
